## RFC 3045 — Vendor Information in root DSE (Informational)

Status: Informational. Attributes are optional. `vendorName` (1.3.6.1.1.4)
and `vendorVersion` (1.3.6.1.1.5).

| # | Requirement | § | Level | Class | Profile |
|---|------------|----|-------|-------|---------|
| rfc3045-01 | `vendorName` is SINGLE-VALUE and NO-USER-MODIFICATION if present in root DSE | 2.1 | MUST | A | Standard |
| rfc3045-02 | Servers MAY restrict access to `vendorName` / `vendorVersion`; clients MUST NOT expect them | 2 | MAY/MUST NOT | B | — |

**Test strategy:**
- rfc3045-01: Read root DSE, request vendorName. If present, verify it's a single value. (PASS/AUTO_PASS if absent.)
- rfc3045-02: Class B — client-side requirement.

**Suites module:** `src/bauble/suites/rfc3045.py`

## RFC 4525 — Modify-Increment Extension (Informational)

Defines a new Modify operation type `increment` (3). Feature OID
1.3.6.1.1.14 in `supportedFeatures`.

| # | Requirement | § | Level | Class | Profile |
|---|------------|----|-------|-------|---------|
| rfc4525-01 | Server supporting increment publishes 1.3.6.1.1.14 in supportedFeatures | 2 | SHOULD | B | Standard |
| rfc4525-02 | Increment operation adds specified value to existing attribute values | 2 | SHALL | A | Standard |
| rfc4525-03 | Increment with multiple values returns `protocolError` | 2 | — | A | Standard |
| rfc4525-04 | Increment on non-incrementable attribute returns `constraintViolation` or appropriate error | 2 | — | A | Standard |

**Test strategy:**
- rfc4525-02: Add an entry with `uidNumber: 1000`. Modify-increment by 1. Read back, verify `uidNumber: 1001`.
- rfc4525-03: Send an increment request with two values. Expect `protocolError`.
- rfc4525-04: Try increment on `cn` (Directory String). Expect `constraintViolation` or `objectClassViolation`.

**Suites module:** `src/bauble/suites/rfc4525.py`

Allows empty `and` (`(&)`) and `or` (`(|)`) filter sets. Feature OID

| # | Requirement | § | Level | Class | Profile |
|---|------------|----|-------|-------|---------|
| rfc4526-01 | `(&)` evaluates to True | 2 | SHALL | A | Standard |

**Suites module:** `src/bauble/suites/rfc4526.py`

## RFC 4527 — Read Entry Controls (Standards Track)

Pre-Read (1.3.6.1.1.13.1) and Post-Read (1.3.6.1.1.13.2) controls.

| # | Requirement | § | Level | Class | Profile |
|---|------------|----|-------|-------|---------|
| rfc4527-01 | Pre-Read request on Modify returns entry before update | 3.1 | — | A | Advanced |
| rfc4527-02 | Post-Read request on Modify returns entry after update | 3.2 | — | A | Advanced |
| rfc4527-03 | Post-Read request on Add returns newly created entry | 3.2 | — | A | Advanced |
| rfc4527-04 | Pre-Read request on Delete returns entry before deletion | 3.1 | — | A | Advanced |
| rfc4527-05 | No response control if update fails | 3.1/3.2 | — | A | Advanced |
| rfc4527-06 | Operation and control processing are one atomic action | 3 | MUST | B | Advanced |

**Test strategy:**
- rfc4527-01: Create temp entry. Modify with Pre-Read control requesting all attributes. Verify response control contains pre-modification values.
- rfc4527-02: Same modify with Post-Read control. Verify response contains post-modification values.
- rfc4527-03: Add entry with Post-Read control. Verify response contains the new entry's attributes including server-assigned operational attrs.
- rfc4527-04: Delete with Pre-Read control. Verify response contains the entry before deletion.
- rfc4527-05: Try a failing Modify (e.g., noSuchObject) with Pre-Read control. Verify no response control.

**Suites module:** `src/bauble/suites/rfc4527.py`

## RFC 4528 — Assertion Control (Standards Track)

Defines the Assertion Control (controlType 1.3.6.1.1.12). If the filter
evaluates TRUE, the operation proceeds. If FALSE or Undefined, returns
`assertionFailed` (122).

| # | Requirement | § | Level | Class | Profile |
|---|------------|----|-------|-------|---------|
| rfc4528-01 | Operation with TRUE assertion filter proceeds normally | 3 | — | A | Standard |
| rfc4528-02 | Operation with FALSE assertion filter returns `assertionFailed` (122) | 3 | — | A | Standard |
| rfc4528-03 | Operation with Undefined assertion filter returns `assertionFailed` (122) | 3 | — | A | Standard |
| rfc4528-04 | Assertion control works with Search (baseObject) | 3 | — | A | Standard |
| rfc4528-05 | Assertion control works with Delete | 3 | — | A | Standard |

**Test strategy:**
- rfc4528-01: Modify with assertion `(objectClass=*)` on existing entry — succeeds.
- rfc4528-02: Modify with assertion `(objectClass=doesNotExist)` — returns 122.
- rfc4528-03: Search with assertion `(objectClass=doesNotExist)` on baseObject — returns 122.
- rfc4528-04: Search subtree from `dc=bauble,dc=test` with assertion `(objectClass=*)` — returns entries.
- rfc4528-05: Delete with assertion `(objectClass=*)` — succeeds.

**Suites module:** `src/bauble/suites/rfc4528.py`

## RFC 4530 — entryUUID Operational Attribute (Standards Track)

Defines `entryUUID` (1.3.6.1.1.16.4), UUID syntax, `uuidMatch` and
`uuidOrderingMatch` matching rules.

| # | Requirement | § | Level | Class | Profile |
|---|------------|----|-------|-------|---------|
| rfc4530-01 | Server SHALL assign a UUID to each entry upon addition | 2.4 | SHALL | A | Standard |
| rfc4530-02 | entryUUID is SINGLE-VALUE, NO-USER-MODIFICATION | 2.4 | — | A | Standard |
| rfc4530-03 | UUID values are in RFC 4122 string representation (xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx) | 2.1 | — | A | Standard |
| rfc4530-04 | entryUUID is immutable across reads | 2.4 | — | A | Standard |

**Test strategy:**
- rfc4530-01: Search any entry with `+` (all operational). Assert `entryUUID` is present.
- rfc4530-02: Verify exactly one entryUUID value. Attempt to modify entryUUID — expect error.
- rfc4530-03: Verify value matches regex `[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}`.
- rfc4530-04: Read entryUUID twice, assert values are identical.

**Suites module:** `src/bauble/suites/rfc4530.py`

## RFC 3866 — Language Tags and Ranges (Standards Track)

Obsoletes RFC 2596. Defines language tag options (`lang-en-US`) and
language range options (`lang-en-`). Feature OIDs 1.3.6.1.4.1.4203.1.5.4
(tags) and 1.3.6.1.4.1.4203.1.5.5 (ranges).

| # | Requirement | § | Level | Class | Profile |
|---|------------|----|-------|-------|---------|
| rfc3866-01 | Server accepts add with language-tagged attribute values | 2.5 | MUST | A | Standard |
| rfc3866-02 | Search filter with language tag option matches only same-tag values | 2.2 | — | A | Standard |
| rfc3866-03 | Language range option matches all language tags with matching prefix | 3.1 | — | A | Standard |
| rfc3866-04 | `lang-` range matches all language-tagged values | 3.1 | — | A | Standard |
| rfc3866-05 | Language range option on add/modify returns error (ranges are not tagging options) | 3 | SHALL | A | Standard |

**Test strategy:**
- rfc3866-01: Add entry with `description;lang-en: Hello` and `description;lang-de: Hallo`. Verify both stored.
- rfc3866-02: Search with filter `(description;lang-en=Hello)` — matches only the en value.
- rfc3866-03: Search requesting `description;lang-en-` — returns both `description;lang-en` and `description;lang-en-US` if present.
- rfc3866-04: Search requesting `description;lang-` — returns all language-tagged descriptions.
- rfc3866-05: Try to add with `description;lang-en-` (range as option) — expect error.

**Suites module:** `src/bauble/suites/rfc3866.py`

## RFC 3876 — Matched Values Control (Standards Track)

ValuesReturnFilter control (1.2.826.0.1.3344810.2.3). Returns only
attribute values matching a "values return" filter.

| # | Requirement | § | Level | Class | Profile |
|---|------------|----|-------|-------|---------|
| rfc3876-01 | Search with valuesReturnFilter returns only matching values | 2 | MUST | A | Standard |
| rfc3876-02 | Attribute with no matching values is returned with empty value set | 2 | — | A | Standard |
| rfc3876-03 | Non-critical control on non-Search operation is ignored | 2 | MUST | A | Standard |
| rfc3876-04 | Critical control on non-Search operation returns `unavailableCriticalExtension` | 2 | MUST | A | Standard |

**Test strategy:**
- rfc3876-01: Search alice with attributes `mail`, valuesReturnFilter `(mail=*hotmail*)`. If alice has both gmail and hotmail, only hotmail returned.
- rfc3876-02: Search with valuesReturnFilter `(mail=no-match)` — attribute `mail` returned empty.
- rfc3876-03: Add valuesReturnFilter (non-critical) to a Compare op — server ignores it, compare proceeds.
- rfc3876-04: Add critical valuesReturnFilter to a Compare op — returns `unavailableCriticalExtension`.

**Suites module:** `src/bauble/suites/rfc3876.py`

## RFC 4520 Note

RFC 4520 (IANA Considerations for LDAP, BCP 64) is a procedural document
defining registration policies for LDAP protocol elements. It contains no
testable assertions against an LDAP server. Documented for completeness.

## Implementation Order

1. **entryUUID** (4530) + **entryDN** (5020) — simplest, highest value operational attributes
2. **Authorization State** (4513 §4.1) — fills compliance gap in auth behavior
3. **Absolute True/False Filters** (4526) — trivial to implement
4. **Vendor Info** (3045) — trivial root DSE check
5. **Attributes by Object Class** (4529) — simple search extension
6. **Modify-Increment** (4525) — requires raw wire layer for increment op
7. **Assertion Control** (4528) — ldap3 constructible control
8. **Authorization Identity Controls** (3829) — bind control
9. **Language Tags** (3866) — requires creating entries with tagged values
10. **Matched Values Control** (3876) — BER-encoded control value
11. **Read Entry Controls** (4527) — more complex, Pre/Post-Read
12. **Don't Use Copy** (6171) — advertisement only, single assertion
